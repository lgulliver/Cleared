# ForeverDungeonComplete — design

Date: 2026-11-13
Status: draft, awaiting approval (builder check done)

## Intent

Retail WoW tells you when you've finished a dungeon. WoW Forever (interface `16001`, product `wowf`) tells you nothing: you kill the last boss and have to work out yourself whether you're done. This addon adds that moment back: a small toast on each boss kill showing progress, and a big "Dungeon Complete" banner when every boss counted for that dungeon is dead.

Personal project, published the same way as the sibling addon `ForeverSkillManager` (`~/repos/forever-skills`).

## Goals

- Toast for each counted boss kill: boss name and progress, e.g. `Lord Roccor defeated  2/21`.
- When the last counted boss dies: a centre-screen banner (`DUNGEON COMPLETE`, dungeon or wing name, `N/N`, elapsed time) with a sound. It fades after about 5 seconds.
- Covers every 5/10-player dungeon in the Forever client, including Forever-only ones (Demon Fall Canyon, Karazhan Crypts, The Drowned City, Blackmaw Hold, etc.).
- Boss data comes from the game client's own tables, not from hand-typed lists.
- Progress survives `/reload` and disconnects within the same instance copy.

## Non-goals

- Raids (v1). The data is in the same table (`InstanceType 2`), so adding them later is cheap.
- Loot display, timers or leaderboards, a boss list/tracker window, party sync.
- Detecting bosses through the combat log (see Approaches). That's only added if testing proves it's needed.

## Anti-goals

- **A dungeon that can never complete.** If optional or rare bosses count, the banner never fires. Getting this wrong is worse than having no addon.
- **False completes,** e.g. banner after clearing one Scarlet Monastery wing while saying "Scarlet Monastery 4/7".
- Noise: spam in chat, or toasts for trash.

## Constraints

- Addons have no network access. All data is baked into the addon as Lua.
- Data source: wago.tools DB2 exports for the Forever build (`wowf`, currently `1.60.1.70938`):
  - `DungeonEncounter`: `ID`, `Name_lang`, `MapID`, `DifficultyID`, `OrderIndex`, `Flags`
  - `Map`: `ID`, `MapName_lang`, `InstanceType` (1 = dungeon, 2 = raid)
  - URL pattern: `https://wago.tools/db2/<Table>/csv?build=<build>`
- Wowhead is a manual cross-check only. Its ToS bans scraping, and it doesn't expose encounter IDs.
- Encounter IDs differ between Forever and Classic Era (VanCleef is `2747` in Forever), so only Forever builds are used.
- The data has leftover rows: Season of Discovery difficulties (`198`, `201`, `215`) in BFD/Gnomeregan/Sunken Temple, Test Dungeon (`13`), world bosses on map `0`, an unnamed map `3002`, and BFD has negative `OrderIndex` values.

## Approaches considered

1. **`ENCOUNTER_END` by encounter ID — chosen.** The game fires `ENCOUNTER_END(encounterID, name, difficultyID, groupSize, success)`. The IDs match `DungeonEncounter.ID` directly, and multi-NPC encounters arrive as one event. Risk: some old dungeon bosses might not fire encounter events in Forever.
2. **Combat log `UNIT_DIED` by NPC ID.** Works without encounter scripting, but needs an NPC ID mapping the DungeonEncounter table doesn't have, extra logic for multi-NPC bosses, and misses kills out of range. Rejected as the primary method.
3. **Hybrid.** Option 1, plus combat-log fallbacks for individual bosses that testing shows don't fire. Kept as a future extension. The exceptions format leaves room for it, but no fallback code ships in v1.

Agreed with the user: option 1, built so 3 can be added later.

## Design

### Repo layout (mirrors ForeverSkillManager)

```
forever-dungeon-complete/
  ForeverDungeonComplete/
    ForeverDungeonComplete.toc      ## Interface: 16001
    Data.lua                        generated, do not edit
    Overrides.lua                   hand-maintained exceptions
    ForeverDungeonComplete.lua      events, progress, UI, slash commands
  tools/gen_data.py                 wago CSV -> Data.lua
  .github/workflows/{lint,release}.yml   copied from forever-skills
  .luacheckrc .editorconfig .gitignore LICENSE README.md CHANGELOG.md
```

### Generated data (`tools/gen_data.py` → `Data.lua`)

- Python 3, stdlib only. Arguments: `--build <version>`, defaulting to the newest `wowf` build from `https://wago.tools/api/builds`.
- Keep maps with `InstanceType == 1`, and encounters with `DifficultyID == 0` and a known, named map. Drop map `0` and Test Dungeon `13`.
- Output, sorted by MapID and then OrderIndex so diffs stay stable:

```lua
-- Generated by tools/gen_data.py from wago.tools build 1.60.1.70938. Do not edit.
local _, ns = ...
ns.Build = "1.60.1.70938"
ns.Dungeons = {
  [230] = { name = "Blackrock Depths", encounters = { 227, 228, ... } },
}
ns.Encounters = {
  [227] = { map = 230, name = "High Interrogator Gerstahn", order = 0, flags = 1024 },
}
```

`Flags` is copied into `Data.lua` for reference only (my call). Nothing at runtime reads it, and it isn't used to mark encounters optional automatically, because what the bits mean isn't confirmed. Whether an encounter is optional is decided only by `Overrides.lua`.

Re-run it after each Forever patch, review the diff, and commit.

### Overrides (`Overrides.lua`, hand-maintained)

Three jobs:

**0. Disabled dungeons (decided by the user).** `ns.Disabled = { [mapID] = "reason" }`. A disabled dungeon gets no toasts and no banner. Instead, one chat line on entry says it isn't supported yet and gives the reason. This covers dungeons whose bosses are known not to fire `ENCOUNTER_END`, until combat-log fallbacks exist. `/fdc debug` still prints events inside disabled dungeons so they can be re-tested.

**1. Optional encounters.** These still get a toast with a "(bonus)" tag, but don't count toward N. They're never required for completion. Starter list for the builder to verify against Wowhead and in-game:

- Stratholme: Skul, Stonespine, Hearthsinger Forresten, Postmaster Malown, Black Guard Swordsmith, Crimson Hammersmith, Ezra Grimm (rares and quest summons)
- Dire Maul: Lord Hel'nurath, Tsu'zee, Pusillin
- Blackrock Spire: Lord Valthalak (summon), Halycon/Gizrul if not required
- Blackrock Depths: the Ring of Law bosses that aren't guaranteed (the encounter spawns one at random)
- Any Forever-only dungeon encounters that turn out to be optional (verify in-game)

**2. Wings.** One map is split into separately completable sections. Each wing has its own name and list of encounters. The active wing is chosen by the first counted boss killed in that instance copy. After that, only that wing's encounters count, and the banner shows the wing name.

| Map | Wings |
|-----|-------|
| 189 Scarlet Monastery | Graveyard (Vishas, Thalnos), Library (Loksey, Doan), Armory (Herod), Cathedral (Fairbanks, Whitemane) |
| 429 Dire Maul | East (Zevrim, Hydrospawn, Lethtendris, Alzzin), West (Tendris, Illyanna, Kalendris, Immol'thar, Tortheldrin), North (Guards, Kromcrush, Cho'Rush, King Gordok) |
| 329 Stratholme | Live (Timmy, Willey, Galford, Balnazzar, Malor, The Unforgiven), Undead (Anastari, Nerub'enkan, Maleki, Barthilas, Ramstein, Rivendare) |
| 229 Blackrock Spire | Lower (Omokk → Wyrmthalak), Upper (Emberseer → Drakkisath) |
| 349 Maraudon | Single wing for v1 (Purple/Orange/Inner routes overlap and Princess is the natural end). Revisit if testing says otherwise. |

**Each wing tracks its own progress (my call).** One instance copy can finish more than one wing, e.g. DM East then West, or LBRS then UBRS. A kill credits the wing that contains it. Each wing gets its own toasts (`2/4` for that wing) and its own banner when it's done. `/fdc status` lists every wing in the current copy that has been started.

**Every encounter on a winged map must be assigned (my call).** It goes either in exactly one wing or in `ns.Optional`. `gen_data.py` loads `Overrides.lua` (a simple parse of the encounter IDs is enough), checks this, and exits non-zero naming any encounter that isn't assigned. So a new boss added by a patch can't ship unassigned and silently break completion. The same check fails on override IDs that no longer exist in the data.

Assigning a kill to a wing by encounter ID is the default. If a wing is ambiguous because a boss appears in two wings, fall back to `C_Map.GetBestMapForUnit("player")` and give the wing a `uiMapIDs` list.

Format sketch:

```lua
ns.Optional = { [2799] = true, ... }            -- encounterID
ns.Wings = {
  [189] = {
    { name = "Scarlet Monastery: Library", encounters = { 446, 447 } },
    ...
  },
}
```

### Runtime

- **Events:** `PLAYER_ENTERING_WORLD`, `ZONE_CHANGED_NEW_AREA`, `ENCOUNTER_END`.
- **Entering an instance:** `GetInstanceInfo()` gives the instance type and `instanceMapID`. If the map is in `ns.Dungeons`, the addon goes active for that map. Otherwise it stays idle.
- **Instance copy identity:** a boss's GUID (from `UnitGUID` on `boss1`/`target` during the encounter, or the GUID of whatever unit is seen first in the instance) contains the zone UID. Format: `Creature-0-serverID-instanceID-zoneUID-npcID-spawnUID`. Saved progress is keyed by `mapID .. ":" .. zoneUID`, so a fresh reset starts at 0 and a reload/DC resumes. If no GUID is available yet, the key is pending, and the first kill sets it. How exactly the GUID is captured is left to the builder.
- **On `ENCOUNTER_END` with `success == 1`:** if the encounter belongs to the active map and isn't already recorded, record it with a timestamp. The first counted kill also records the run's start time (and picks the wing, if applicable). Then show a toast. If the counted set is now complete, show the banner after a short delay so it doesn't land on top of the last toast.
- **Elapsed time** = completion time minus the time the run was first entered. Entry time is saved with the run.
- **SavedVariables:** `ForeverDungeonCompleteCharDB = { settings = {...}, runs = { [key] = { map, wing, entered, killed = { [encID] = time }, completed } } }`. Runs older than 24h are pruned on login.
- **Already completed:** if the banner has already fired for this run, it never fires again.

### UI

```
Toast (top centre, under the zone text, stacks up to 3, ~3s each):
  [boss skull]  Lord Roccor defeated     2/21
  [boss skull]  Skul defeated            (bonus)

Banner (centre screen, ~5s, fade in/out, sound):
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        DUNGEON COMPLETE
   Scarlet Monastery: Cathedral
          2/2 · 18m 04s
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

Plain frames and font strings, no library dependencies. The builder picks the sound kit (something celebratory, like the level-up or quest-complete sound).

### Slash commands (`/fdc`)

| Command | Does |
|---------|------|
| `/fdc` | Open settings (Esc > Options > AddOns) |
| `/fdc status` | Print the current dungeon/wing, killed and remaining counted bosses |
| `/fdc test` | Show a sample toast and banner |
| `/fdc reset` | Forget progress for the current instance |
| `/fdc debug` | Toggle printing of every `ENCOUNTER_END` with its ID (to find bosses that don't fire, or wrong IDs) |

### Settings (per character)

Toasts on/off, banner on/off, sound on/off. That's all.

## Verification

- `luacheck` passes in CI, the same as forever-skills.
- `gen_data.py` output is committed. A re-run against the same build gives an identical file.
- Manual in-game checks (they can't be automated):
  1. `/fdc debug` in one short dungeon (Ragefire Chasm or Deadmines). Confirm every boss fires `ENCOUNTER_END` with the expected ID.
  2. A full clear shows the toasts in order and the banner on the last boss.
  3. `/reload` mid-run: progress is kept.
  4. Leave, reset the instance, re-enter: progress is back at 0.
  5. One SM wing: the banner names that wing and gives the right count.

Release gate (decided by the user): v1 ships after step 1 has been run in a handful of dungeons, at least one classic, one winged and one Forever-only. Any dungeon where a counted boss doesn't fire goes into `ns.Disabled`. The rest are confirmed through `/fdc debug` during normal play after release. A dungeon that's confirmed broken leads to approach 3 for that dungeon.

## Amendment 2026-11-14: no instance GUIDs

In-game testing showed that `UnitGUID` returns a secret value inside Forever dungeons, both for `target` and for nameplates, so the zone UID can't be read. Agreed with the user:

- Runs are keyed by map ID. A saved run is resumed when the dungeon is re-entered within 30 minutes of it last being seen. Last seen is updated every 60 s while inside, on each kill and on `PLAYER_LEAVING_WORLD`. Otherwise a new run starts.
- `CHAT_MSG_SYSTEM` matching `INSTANCE_RESET_SUCCESS` drops the saved run for that dungeon.
- A counted or optional boss already in the run dying again more than 60 s later means a new copy. The run restarts at that kill.
- Accepted risk: a reset that isn't seen, followed by re-entry within 30 minutes, starts counts from the old run until a repeat kill. Bosses killed before that point add to the old run, so an early banner is possible. `/fdc reset` is the manual fix.

- How the instance GUID is captured.
- Settings panel layout (follow how ForeverSkillManager uses the Settings API).
- Final membership of the optional and wing lists, verified against Wowhead and in-game. The starter lists above are the default.
